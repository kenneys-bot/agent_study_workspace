# 风险清单（v0.1.0 / T31 / #32）

日期：2026-11-12（Asia/Shanghai）｜范围：M0–M7 全部阶段报告中**未解决**的风险与本轮
运维核对发现的问题。已解决项（如 144 用例双端一致、ADR-0006 数据库落地、备份恢复/回滚/
索引重建已演练）不再列入。

严重度定义（个人项目口径，非机构标准）：

- **High**：影响发布可信度或可能造成安全/数据后果，负责人需在对外汇报前知情；
- **Medium**：当前单机演示可用，但扩展、故障或复现时会出问题；
- **Low**：文档/复现性/质量证据的已知局限，不阻塞演示。

计数：**High 7　Medium 8　Low 3　Critical 0**。没有已确认的应用层高危越权/数据泄露
缺陷；ChromaDB 依赖公告属依赖侧 High（当前部署不可达），见 R-06。**不能据此声称
「无高危风险」**。

## 4. 与验收门槛的关系（不粉饰）

- 计划 §7 的 Recall@5 未达标（R-01）、引用支持度未测（R-02）、24h/压测未跑（R-05），
  因此**不能声称 M7 工程门槛全部通过**，也不能把 M7 标为 `ACCEPTED`。
- 「未处理的高危访问控制/数据泄露缺陷为 0」仅对**应用层已实现路径**成立（M7-03 测试
  通过）；凭据轮换（R-03）与依赖公告（R-06）仍是 High，整体风险不为 0。
- 以上风险不阻塞**个人演示**，但必须在对外汇报与简历表述中如实标注边界。

## 5. 复核触发条件

1. 每次发布（`make release-verify`）后复核 R-06/R-07/R-11；
2. 修改检索/知识/规则/模型后复核 R-01/R-02（需重新评测）；
3. 增加副本、跨机抓取或对外端口前复核 R-09/R-10/R-11/R-12；
4. 负责人完成凭据轮换后关闭 R-03。
