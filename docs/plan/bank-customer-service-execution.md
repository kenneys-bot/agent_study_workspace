默认一次会话完成一个里程碑，按任务ID依次执行；阶段完成后交付验收报告并等负责人接受，再进入下一阶段。负责人明确要求连续执行时，可继续不依赖未决条件的下一阶段，但报告仍保留待验收状态；实际生产发布需要明确授权。

## 2. 第一次接手的操作顺序

1. 读取仓库适用的AGENTS.md等约束；检查Git状态、分支、SHA及现有diff，识别用户已有修改。
2. 阅读需求计划和本阶段任务，列出可执行项、环境阻碍和外部依赖。先自行查明文件和配置事实，再提问缺失的访问方式或业务决策。
3. 在独立分支/工作树实施。分支默认 `codex/bank-assistant-m0` 等；如用户有分支规范则遵循。保留既有未提交改动，不能自动reset或覆盖。
4. 如无共享Git远程或Ubuntu访问方式，完成本机可做部分；将双机步骤BLOCKED并说明负责人需提供什么。不得虚构SSH连接、服务器配置或部署结果。
5. M0创建进度文件与阶段报告目录，记录当前基线。以后每次会话从状态文件恢复，不重新无差别扫描全部仓库。

## 3. 每个任务的固定执行循环

1. 定位：读取任务涉及实现、调用方、模型和测试；核对系统契约。
2. 验证：缺陷先最小复现；新功能先确定输入、输出、状态和验收用例。
3. 实现：完成最小完整业务路径；兼容性变化同步schema、迁移与文档。单元测试使用替身，正式演示使用真实服务。
4. 测试：执行与改动匹配的单元/集成/契约/端到端测试；修改数据、权限、事务时覆盖负向和并发路径。
5. 同步：只提交本任务变更；按照Git流程将指定SHA同步到Ubuntu。实验前核对两端SHA，服务器工作树应干净。
6. 取证：正式评测/训练在Ubuntu运行，将大产物存入ARTIFACT_ROOT；仓库保存摘要、哈希和相对引用。
7. 更新：更新状态文件和阶段报告，给出下一条可执行任务。未通过门槛时继续修复或标记阻碍，不写“已完成”。

如要替换本计划的默认技术方案，先核验环境和维护成本，写明理由、影响与迁移方式；涉及业务范围或外部数据使用的改变交负责人决定。不得为通过验收移除困难样本、改低阈值或把真实服务改成未标识的mock。

## 4. 目标命令接口

以下命令目前是待实现的交付契约，不能直接假定仓库已有。M0/M1创建Makefile或等价脚本后，README记录真实用法。命令失败必须返回非零退出码。

| 目标命令 | 行为 | 默认执行位置 |
|---|---|---|
| make doctor | 检查依赖、环境变量存在性、目录与端口；不打印秘密值 | 两端 |
| make test-unit | 无网络、无真实凭据的单元测试 | 本机/Ubuntu |
| make test-integration | 使用独立 `*_test` 库验证迁移、事务、权限、索引（经 SSH 隧道） | Mac（需隧道） |
| make test-e2e | 启动隔离演示环境并验证用户路径 | 两端 |
| make build | 锁定依赖构建应用和前端 | 两端 |
| make up / make down | 启停指定开发/演示环境 | 两端 |
| make smoke | 检查存活、就绪、基本正常与异常路径 | 两端 |
| make seed-demo | 只导入合成演示数据，幂等，不清库 | Ubuntu优先 |
| make sync-check | 报告双方SHA与相关未提交状态，不自动覆盖 | 本机发起 |
| make eval EVAL_CONFIG=path | 运行固定评测并输出manifest和结果 | Ubuntu |
| make train TRAIN_CONFIG=path | 资源检查、dry-run/训练、产物记录 | Ubuntu，条件任务 |
| make backup / make restore-check | 备份及在独立目标 `*_restore_check` 恢复验证；后者不覆盖源库与演示库 | Ubuntu |

云模型测试另设显式开关、费用上限与样本上限；测试失败不能无上限重试产生费用。生产发布不由通用 `make up` 隐式触发。

**数据库命令的前置条件（ADR-0006）**：数据库唯一实例在 Ubuntu，Mac 不部署本地数据库。`test-integration` / `seed-demo` / `backup` / `restore-check` / `alembic` 等命令依赖 SSH 本地端口转发：

```bash
ssh -N -L 15432:127.0.0.1:5432 my-ubuntu-server   # Mac 上保持运行
# DATABASE_URL=postgresql+psycopg://<user>:<password>@127.0.0.1:15432/<db>
```

隧道或服务器不可达时，这些命令必须非零退出并给出可读原因，或把对应验收标记 BLOCKED；禁止静默改用 SQLite/mock 后宣称通过。`make test-unit` 不依赖数据库，始终可跑。集成测试只允许连接 `*_test` 库；恢复验证只允许写入 `*_restore_check`。

```markdown

相关需求：FR-xx

## 交付内容与文件
## 验收逐条结果
| 验收项 | PASS/FAIL/NOT_RUN | 执行命令 | 证据位置 |
|---|---|---|---|

## 指标与样本量
## 失败、跳过、环境限制
## 数据/模型/知识/规则/索引版本
## 兼容性与迁移
## 遗留风险和外部依赖
## 下一阶段入口
## 负责人验收
```

PASS必须来自实际执行或可核查静态证据，并标明验证类型；代码存在、HTTP 200、测试被跳过、模型生成截图都不等价于业务验收通过。

## 7. 需要负责人输入的边界

- Ubuntu连接方式、仓库访问、云模型凭据与预算：通过安全配置提供；可继续与之无关的本机任务。
- 服务器或 SSH 隧道不可达：单元测试与前端工作可继续；集成测试、迁移、seed、备份恢复标记 BLOCKED 并说明原因，不得用 SQLite/mock 替代后宣称通过（ADR-0006）。
- 数据来源/授权、真实银行知识与规则、业务验收负责人：在使用对应资料前取得；此前使用合成数据推进。
- GPU和显存不足：交付资源报告及替代方案，微调可标记条件不满足，不影响已验证的云模型路线。
- 进入真实银行环境、对外开放服务、产生超预算成本、生产迁移/发布：准备完整可审查方案后由负责人决定。
- 本项目没有业务方：如实停在生产就绪，不宣称上线；若未来出现业务方，按计划书附录A推进。真实使用不能由模拟数据或个人服务器代替。
