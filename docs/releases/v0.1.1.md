## 1. 本次发布内容（T37 / #37）

把 T36 在**评测层**验证过的两项检索改进落到**生产链路**，消除 M6 报告的
「改进只在评测层」caveat：

1. **索引文本**：`knowledge/indexing.py` 的 embedding 输入按
   `embedding_text=title_chunk` 拼入知识标题；`KnowledgeChunk.text` 与码点
   区间仍是原文区间，引用语义不变（ADR-0005）。
2. **生产重排**：`SuggestionService` 先召回候选池（20），再按与评测**同一份**
   实现（`knowledge/ranking.py`）做确定性词面重排（α=0.2），并在
   `retrieval_snapshot` 记录 `rerank_status`、α、候选池、前后顺序。
3. 配置默认值与 T36 采用的评测配置同义：`RETRIEVAL_EMBEDDING_TEXT=title_chunk`、
   `RETRIEVAL_RERANK_ALPHA=0.2`、`RETRIEVAL_RERANK_POOL=20`，均可显式关闭回退。

后一次运行的 `retrieval_snapshot`：`index_embedding_text=title_chunk`、
`rerank_status=applied`、`candidate_hit_count=20`、重排 `before`/`delivered`
不同（`moved=true`），交付 5 条；2 条引用均能打开原文（quote 在原文区间内）。
复现：`curl` 同上查询到 `/api/v1/suggestions`，或离线跑
`uv run pytest tests/test_retrieval_production.py -q`。

> 说明：`retrieval_snapshot.chunks[].score` 是**向量相似度**；交付顺序是
> 向量相似度 + α×词面覆盖率，因此重排后相邻 score 不保证单调——与评测采用的
> 公式一致，不是缺陷。

## 7. 明确不包含 / 不声明

- 不是生产部署，不构成任何机构的部署许可或业务验收（计划书 §1/§7）。
- 服务器是负责人个人 Ubuntu 工作站，非专用生产环境；无高可用、无多副本、无 7×24 保障。
- 本次**没有**在评测集上重跑：冻结 test 的指标仍是 T36 的评测口径（Recall@5
  0.944、complaint 0.867），生产收益只以上面的端到端对比、索引身份与
  `retrieval_snapshot` 为证据，不把评测分数直接当线上业务收益。
- 重排是**确定性词面**重排，不是语义 reranker，也没有调用模型；不宣称它提升
  所有场景，只宣称与评测采用配置一致、可审计、可关闭。
- 未执行真实供应商限流/断网、真实数据库停机、24 小时长跑与 10 并发压测；
  见 [M7 验收报告](../milestones/M7-report.md) 与 [风险清单](../ops/risk-register.md)。
- 未创建 Git tag、未 push；tag 由负责人在合并后创建。
