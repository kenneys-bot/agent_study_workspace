# PostgreSQL 18 只部署在 Ubuntu：Mac 通过 SSH 隧道访问

状态：accepted（2026-11-12）。**取代 ADR-0002 中「Mac 用 Docker 跑 PostgreSQL」「两机数据库版本一致」的部分**；ADR-0002 其余结论（PostgreSQL 是业务事实源、Chroma 只是可重建索引、SQLite 只用于单元测试替身）继续有效。

## 背景

本项目的数据库长期方案原本是「Mac 与 Ubuntu 各跑一套 PostgreSQL 18」。实际条件是一个人在 Mac 上开发、Ubuntu 是一台家用桌面机（也是评测/数据/部署演练的机器）。两处各跑一套会带来双份初始化、双份迁移、双份备份、两套密码，以及"哪一份才是真实数据"的持续歧义；同时 Mac 本机多一个需要维护的容器与端口占用。

2026-11-12 决定：数据库集中到唯一位置。这是一次**部署位置调整，不是生产化**——本项目仍是个人展示项目，没有真实业务方与生产部署许可。

## 决策

1. **唯一实例**：PostgreSQL 18 只运行在 Ubuntu（`my-ubuntu-server`；Wi-Fi `192.168.1.27`、有线 `192.168.5.10`）。容器端口绑定 `127.0.0.1:5432`（仅回环），**不暴露到局域网或公网**。
2. **Mac 不部署数据库**：不安装、不创建、不启动本地 PostgreSQL（不跑容器、不装 Homebrew PG 服务、不建本地 data 目录）。Mac 只保留可选的 `psql` 客户端或 DBX 这类图形工具用于查看。
3. **访问方式：SSH 本地端口转发**。在 Mac 上执行：

   ```bash
   ssh -N -L 15432:127.0.0.1:5432 my-ubuntu-server
   ```

   之后 Mac 的 `127.0.0.1:15432` 才指向服务器数据库。**`localhost` 永远指当前机器**——没有建立转发，Mac 上就没有可连的数据库，这一点必须显式存在，不能靠"本地恰好有一个 PG"掩盖。

   ```text
   DATABASE_URL=postgresql+psycopg://<user>:<password>@127.0.0.1:15432/<database>
   ```

   选 15432 而不是 5432 是刻意的：避免与任何本机 5432 混淆，也让"必须先建隧道"成为不可忽略的步骤。服务器容器内部仍监听 5432，转发的目标端是 `127.0.0.1:5432`。

4. **数据库隔离（同一实例内按用途分库，自动化测试不得触碰演示数据）**：

   | 数据库 | 用途 | 谁可以清空 |
   |---|---|---|
   | `bank_assistant_dev` | 日常开发 | 开发者（显式命令） |
   | `bank_assistant_demo` | 演示数据（`make seed-demo` 写入） | 只允许 `make seed-demo` 幂等写入，不允许自动化测试清空 |
   | `bank_assistant_test` | 集成测试专用 | 测试脚本 |
   | `bank_assistant_restore_check` | 备份恢复验证的独立目标库 | 恢复演练 |

   规则：测试只允许连接 `*_test`；恢复验证只允许恢复到 `*_restore_check`，**不得覆盖源库或演示库**；备份从 `dev`/`demo` 生成，不写回源库。

5. **服务器不可达时的失败语义**：单元测试（无数据库依赖）可以继续；所有需要真实数据库的任务（集成测试、迁移、`seed-demo`、备份/恢复验证）必须**显式失败并给出可读原因，或把对应验收标记 BLOCKED**。禁止静默切换到 SQLite 或 mock 之后宣称验收通过。
6. **凭据**：只存在 Mac 的 `.env` 与服务器自身配置中，不进 Git、不进日志；SSH 使用密钥，不使用密码。

## 不做的事

- 不把 PostgreSQL 端口映射到 `0.0.0.0`，不加防火墙放行；需要远程访问时一律走 SSH 隧道。
- 不因为"集中部署在服务器"就宣称生产环境、生产上线或服务了多少坐席。
- 不在本次改造中创建/迁移/删除任何数据库、启停任何容器或修改凭据——本次只改计划与文档。

## 后果

- Mac 上的 `make test-integration`、`make seed-demo`、`make backup`、`make restore-check` 都依赖隧道已建立；`make doctor` 应检查「隧道 + 目标库可达性」，而不是检查本机 Docker/PG。
- 迁移只需在一处执行；备份只需从一处生成；ADR-0002 里的「两机数据库版本一致」问题自然消失，该要求随之删除。
- 联网是开发前置条件之一：Ubuntu 不可达时，能做的只有单元测试、前端与文档工作。
- 他人复现本项目需要自备服务器与隧道（记录在 `docs/environment.md` 的已知限制里）。
- 历史阶段的验收报告（M0–M3）成文于本决策之前，报告中出现的"本机 Docker PG / 两机集成测试"属于当时事实，保留原文并加注历史说明，不回填改写。
