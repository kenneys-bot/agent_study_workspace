# 单仓、根目录即产品：学习内容归档而不删除

状态：accepted（2026-11-12）

仓库最初是个人 AI Agent 学习仓（`learn_20260205/`、`learn_20260210/`、notebook、`八股记录.md`），但现在交付的是一个要对面试官展示的银行坐席辅助／质检系统，根目录的混乱会被直接读成工程能力不足。决定：保持单仓，**根目录即产品仓库**——后端用 `src/` 布局（`src/bank_assistant/`），测试、迁移、前端、部署、文档各自分层；学习内容整体 `git mv` 到 `archive/learning/`，原 16 篇设计文档移到 `archive/design-v0/`。这次移动是一次**纯移动提交**（只改路径，不改任何一行代码内容），便于 review 和整段回滚。分支前缀用 `feat/`、`fix/`、`refactor/`，替代计划书 v1.0 里的 `codex/`。

## 考虑过的方案

- **只把应用提到子目录、其它不动**：根目录仍然乱，且 `learn_20260210/app` 这个名字会继续误导后来者与面试官。
- **拆成两个仓库**（本仓冻结为学习仓、另建干净产品仓）：展示效果最好，但要重复维护 remote 与权限，现在做太早。树干净之后随时可以 `git subtree split` 无损提取，所以先不付这个成本。

## 后果

- `python -m`、pytest、alembic 的路径全部变化；`Makefile` 成为唯一命令入口，README 只记录 Makefile 命令。
- `archive/` 不参与构建，也不被 pytest 收集（`norecursedirs`），只在对照历史时读取。
- 设计文档按里程碑分批重写，不一次性重写 8,268 行：M2 数据/权限、M3 检索/建议、M4 规则/证据/复核、M5 工作台、M7 部署运维；每篇新文档头部写明取代 v0 的哪一篇。
